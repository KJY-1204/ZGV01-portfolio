## ADDED Requirements

### Requirement: 대표 부하 상황의 반복 측정
시스템은 월드 이동, 좀비 다수, 큰 거점, 멀티플레이의 네 상황을 같은 조건으로 반복 측정하고, 상황마다 프레임 시간(평균과 상위 1% 최악), CPU 구분별(스크립트, 렌더, 물리) 비중, 프레임당 GC 할당량을 기록할 수 있어야 한다.

#### Scenario: 같은 조건으로 전후 비교
- **WHEN** 개발자가 같은 상황 절차를 최적화 전과 후에 각각 실행한다
- **THEN** 두 결과가 같은 항목(평균, 상위 1% 최악, CPU 비중, GC 할당)으로 기록되어 직접 비교할 수 있다

#### Scenario: 에디터가 백그라운드일 때
- **WHEN** 에디터 창이 포커스를 잃어 프레임이 거의 진행되지 않는다
- **THEN** 측정은 그 결과를 유효한 수치로 기록하지 않고 프레임이 정상 진행되지 않았음을 알린다

### Requirement: 측정 근거가 있는 최적화만 적용
시스템은 측정으로 확인된 병목에 대해서만 최적화를 적용해야 하며, 각 최적화는 대상 상황의 측정값이 개선되었음을 전후 수치로 보여야 한다.

#### Scenario: 개선이 확인되지 않은 변경
- **WHEN** 최적화 후 대상 상황의 측정값이 개선되지 않거나 다른 상황에서 악화된다
- **THEN** 그 변경은 되돌리거나 유지 사유를 기록한다

### Requirement: 상황별 프레임 예산
시스템은 정해진 기준 환경에서 각 대표 상황이 프레임 예산을 지키도록 해야 한다. 목표는 60fps이며, 평균 프레임 시간 16.7ms 이하를 예산으로 한다. 기준 환경은 이 PC의 개발 빌드이고, 최적화 중의 전후 비교는 같은 PC의 에디터 측정을 상대 비교용으로 쓴다.

#### Scenario: 좀비가 많이 모인 상황
- **WHEN** 기준 수의 좀비가 플레이어 주변에서 활성 상태이다
- **THEN** 프레임 시간이 좀비 다수 상황의 예산 안에 들어온다

#### Scenario: 큰 거점
- **WHEN** 기준 수의 건축물이 설치된 거점 안과 주변에 플레이어가 있다
- **THEN** 프레임 시간이 큰 거점 상황의 예산 안에 들어온다

#### Scenario: 멀티플레이 중
- **WHEN** 호스트와 참가자가 함께 접속해 이동·전투 중이다
- **THEN** 호스트와 참가자 모두 프레임 시간이 멀티플레이 상황의 예산 안에 들어온다

### Requirement: 최적화는 게임 동작을 보존
최적화는 서버 권위로 확정되는 결과(데미지, 사망, 전리품, 인벤토리, 건축, 저장)와 플레이어가 인지하는 좀비의 행동·반응을 바꾸지 않아야 한다.

#### Scenario: 멀리 있는 좀비의 갱신 빈도 감소
- **WHEN** 플레이어에게서 먼 좀비의 갱신 빈도나 표현 비용을 줄인다
- **THEN** 그 좀비가 플레이어 가까이 오면 이전과 같은 감지, 추격, 공격 동작을 보이고 데미지와 전리품 결과는 같다

#### Scenario: 시각 품질 변화
- **WHEN** 최적화가 화면에 보이는 품질(그림자, 효과, 거리별 모델, 풀·나무 밀도)을 낮출 수 있다
- **THEN** 변경 전에 사용자에게 알리고 승인받거나, 화면에서 구별되지 않음을 캡처로 확인한다

### Requirement: 회귀 검증
시스템은 최적화 후에도 기존 EditMode 테스트가 모두 통과하고 컴파일 오류와 콘솔 예외가 없어야 하며, 싱글플레이와 호스트 + 참가자 멀티플레이 경로가 모두 동작해야 한다.

#### Scenario: 최적화 완료 후 검증
- **WHEN** 한 최적화 항목이 끝난다
- **THEN** EditMode 전체가 통과하고, 싱글 실행과 호스트 + 참가자 실행에서 콘솔 예외가 0건이다
